# 적립금 배분 계산기

월 적립금을 종목별 비중으로 배분하고 정수 매수 수량, 실제 매수금액, 잔액을 계산합니다. 흰색 배경의 세로형 카드 화면이며 PC와 모바일에서 같은 순서로 사용합니다.

## 사용

1. 월 적립금을 입력합니다.
2. 종목명·비중·1주 가격을 입력합니다. 입력할 때마다 자동 계산·저장합니다.
3. 종목별 배분액·매수 수량과 상단의 매수금액·잔액을 확인합니다.

비중 합계가 100%가 아니어도 합계에 비례해 배분합니다. 금액은 정수 원 단위로 계산하고, 나눗셈의 나머지가 큰 종목부터 1원씩 배정해 배분 합계가 적립금과 정확히 일치하도록 합니다. 나머지가 같으면 화면의 종목 순서를 따릅니다. 매수 수량은 배분액을 1주 가격으로 나눈 뒤 내립니다. 매수에 쓰지 않은 돈은 잔액으로 남고 다른 종목에 자동 재투자하지 않습니다.

예: 50만 원을 60/20/20 비중과 45,000/25,000/10,000원 주가로 배분하면 30만/10만/10만 원, 6/4/10주입니다. 실제 매수금액은 47만 원, 잔액은 3만 원입니다.

주가는 직접 입력합니다. 배분액이 있는 종목의 가격이 없거나 0이면 해당 매수 수량과 전체 매수금액·잔액은 확정 표시하지 않습니다. 비중은 음수를 허용하지 않고 소수점 4자리까지, 금액은 0~1조 원의 정수까지, 종목은 최대 100개까지 지원합니다. 수수료·세금·최소 주문 단위 등은 반영하지 않습니다.

## 저장·내보내기

- 현재 설정은 이 사이트의 브라우저 `localStorage`의 `pension-dca-settings-v2`에 저장합니다. 서버 동기화는 없습니다.
- 이전 버전의 `pension-dca-rows-v1`, `pension-dca-total-v1`이 있으면 새 형식으로 가져옵니다. 이전 키는 삭제·덮어쓰기하지 않습니다.
- 총액만 수정해도 저장하며, 종목을 모두 삭제한 상태도 유지합니다. 이름의 따옴표·HTML은 일반 텍스트로 처리합니다.
- 잘못된 입력은 오류를 표시하고 유효한 저장값을 덮어쓰지 않습니다. 손상된 기존 설정은 자동 덮어쓰기를 중단하고 불러오기·초기화를 안내합니다. 저장 실패와 다른 탭의 저장값 변경도 안내합니다.
- ‘내보내기’는 전체 설정을 JSON 파일로 저장합니다. ‘불러오기’는 계산기가 내보낸 1MB 이하 JSON을 검증한 뒤 사용자 확인을 거쳐 교체합니다. 금액·비중·형식이 잘못된 파일은 반영하지 않습니다.
- 초기화·불러오기 직전 원본은 `pension-dca-settings-before-replace`에 보관합니다. 가장 최근 교체 직전 자료만 담으므로 별도 파일 백업을 권장합니다. 저장 실패 시 화면에서 계산은 할 수 있지만 설정을 내보내 보관해야 합니다.
- 초기화는 총액을 비우고 기존 기본 5종목(60/20/10/5/5)을 복원합니다. 가격은 비워둡니다.

## 실행·검증

저장소 루트에서 `python3 -m http.server 8000 --bind 127.0.0.1`을 실행하고 `/howtodistribute/`를 엽니다. ES 모듈을 사용하므로 `file://` 대신 HTTP로 실행하세요. 별도 패키지 설치나 빌드는 필요하지 않습니다.

```sh
node --test tests/allocation.test.mjs
python3 tests/allocation_browser.py
```

브라우저 테스트 의존성은 [tests/README.md](../tests/README.md)를 참고하세요. 계산 정확성, 기존 저장 데이터 이전, 자동 저장, 잘못된 입력·손상 데이터·저장 실패, 설정 파일 왕복, 빈 종목 목록 유지와 320/375/600/1440px 화면을 검증합니다.
